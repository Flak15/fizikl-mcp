# Design

## Context

Сейчас: `loadEnvFile()` читает `.env` (корень проекта, затем cwd, не переопределяя уже заданные переменные), `getCredentials()` берёт `LOGIN`/`PASSWORD` из `process.env`, `index.ts` проверяет креды eager при старте с `exit(1)`. Workspace-конфиг `.zcode/config.json` закоммичен (в нём только запись `fizikl`: command + args). Юзер-конфиг `~/.zcode/cli/config.json` уже существует (там `chrome-devtools`). Поведение ZCode из доков: юзер-скоуп **заменяет** одноимённую workspace-запись целиком; `${VAR}`-подстановки в конфиг-файлах нет (только у плагинов). Мотивация — в `proposal.md` (Why).

## Goals / Non-Goals

**Goals:**

- Один источник кредов: окружение процесса, которое собирает MCP-клиент из своего env-блока.
- Репозиторий без секретов и machine-specific конфигурации.
- Убрать кастомный `.env`-лоадер (минус ~15 строк и два пути поиска файла).

**Non-Goals:**

- JWT-механика и персистентность `~/.fizikl-mcp/auth.json` не меняются (ADR-0003 действует).
- OAuth/PAT для Физикла не вводим — у сервиса их нет.
- Мультиаккаунтность не поддерживаем: `auth.json` один на машину, клиенты с разными аккаунтами будут делить refresh-токен. Зафиксировано как ограничение.
- Упаковка в плагин ZCode (вариант D из explore) отклонена как оверкилл.

## Decisions

### 1. B3: workspace-запись удаляем, вся конфигурация — в юзер-скоупе

`~/.zcode/cli/config.json` получает полную самодостаточную запись `fizikl` (command + args + env); `.zcode/config.json` уходит из репозитория.

Альтернативы, отклонённые в explore:

- **B1** (workspace держит command/args, юзер-скоуп добавляет env) — невозможно: слияния полей между скоупами нет, юзер-запись затирает workspace целиком.
- **B2** (полная юзер-запись + workspace-файл как «хинт» для свежих клонов) — на этой машине workspace-файл навсегда мёртвый груз, а на чужой даёт сервер, падающий при старте без кредов; хинт ценой второго места правды.
- **A** (раскоммитить `.zcode/config.json`, добавить в `.gitignore`, шаблон в README) — держит персональный файл в дереве репозитория; раз он всё равно персональный — ему место вне репо.
- **D** (плагин ZCode с `${user_config.KEY}`) — «платформенно-родно», но превращает однофайловый сервер в дистрибутив.

### 2. `loadEnvFile()` и `.env` удаляем полностью, без fallback

Лоадер существовал ради запуска вне клиентского конфига; после переезда единственный его потребитель — smoke, которому хватает inline-env (`LOGIN=… PASSWORD=… npm run smoke`). Альтернатива «оставить как dev-fallback» отклонена: два источника кредов — два места для расхождений, а сама переездная механика уже мягкая (env, заданный клиентом, лоадер и так не переопределял).

### 3. Fail-fast при старте сохраняем, приоритеты не нужны

Раз `.env` нет, `getCredentials()` — чистое чтение `process.env` + та же eager-проверка в `index.ts` с `exit(1)`: конфигурационная ошибка видна сразу в Settings → MCP клиента, а не посреди диалога. Lazy-вариант (ошибка на первом вызове инструмента) отклонён: хуже диагностируется.

### 4. Тексты ошибок: клиенто-независимые, с сохранением контракта тестов

Новые тексты в `config.ts` (нет кредов) и `auth.ts` (провал входа) обязаны содержать слова «LOGIN и PASSWORD» — на них матчится `tests/unit/auth.test.ts`; подсказка — «передайте через env-блок в конфигурации вашего MCP-клиента», без хардкода путей конкретного клиента (пути — в README).

### 5. Креды — только env, не args

Флаги вида `--login …` не рассматриваем: args видны в `ps` другим процессам пользователя; env-блок — стандарт паттерна (GitHub MCP и др.).

## Risks / Trade-offs

- [Свежий клон не автоподключается в ZCode] → README описывает шаг с юзер-скоупом; осознанный размен за репозиторий без machine-specific путей (README больше не извиняется за абсолютный путь).
- [Пароль в plaintext в `~/.zcode/cli/config.json`] → тот же уровень доверия, что `claude_desktop_config.json` и `~/.fizikl-mcp/auth.json`: персональный файл в домашнем каталоге; в git не попадает.
- [Забытый env-блок → сервер падает при старте] → fail-fast-текст объясняет, куда добавить креды.
- [Смена аккаунта = правка конфига клиента] → приемлемо для личного инструмента.

## Migration Plan

На машине пользователя (вне репозитория):

1. Добавить в `~/.zcode/cli/config.json` полную запись `fizikl` с env-блоком (команды для копирования — в README).
2. Применить изменения репозитория (код, доки, `git rm .zcode/config.json`), пересобрать `dist`.
3. Удалить `.env` и строку `.env` из `.gitignore`.
4. Проверить: без env сервер выходит с подсказкой; с env — ZCode показывает connected; `LOGIN=… PASSWORD=… npm run smoke` проходит цикл.

Откат: `git revert` изменений + восстановление `.env` и workspace-конфига (или просто юзер-запись со старым поведением — старый билд читает env в первую очередь).
