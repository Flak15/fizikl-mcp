# Spec Delta

## Purpose

Определяет, откуда MCP-сервер Физикла получает учётные данные и как клиенты его запускают: только переменные окружения из env-блока персонального конфига клиента, без файлов кредов в репозитории.

## ADDED Requirements

### Requirement: Креды берутся из переменных окружения процесса

Сервер SHALL получать учётные данные Физикла исключительно из переменных окружения `LOGIN` и `PASSWORD` запущенного процесса (их задаёт MCP-клиент в env-блоке своей конфигурации). Сервер MUST NOT читать файлы `.env` или иные файлы учётных данных.

#### Scenario: Клиент передал креды через env-блок

- **WHEN** процесс сервера запущен клиентом с заданными `LOGIN` и `PASSWORD` в окружении
- **THEN** сервер стартует и использует эти креды для ленивого входа при первом вызове инструмента

#### Scenario: Частично заданные креды считаются незаданными

- **WHEN** в окружении задан только один из пары `LOGIN`/`PASSWORD`
- **THEN** сервер трактует креды как незаданные (см. требование о fail-fast)

### Requirement: Fail-fast при отсутствии кредов

При старте без кредов сервер MUST завершиться с ненулевым кодом выхода до регистрации инструментов, выдав в stderr русскоязычное сообщение, которое называет переменные `LOGIN`/`PASSWORD` и место их задания — env-блок конфигурации MCP-клиента.

#### Scenario: Запуск без кредов

- **WHEN** процесс сервера запущен без `LOGIN` и `PASSWORD` в окружении
- **THEN** процесс завершается с ненулевым кодом, в stderr — русскоязычная подсказка про env-блок конфига клиента

### Requirement: Ошибка входа указывает на конфиг клиента

При неудачном входе в Физикл сервер SHALL возвращать русскоязычную ошибку, отправляющую проверять `LOGIN`/`PASSWORD` в env-блоке конфигурации MCP-клиента.

#### Scenario: Физикл отверг креды

- **WHEN** сервис авторизации Физикла отвечает на вход ошибкой (например, HTTP 401)
- **THEN** инструмент возвращает ошибку на русском, упоминающую `LOGIN`/`PASSWORD` и env-блок конфига MCP-клиента

### Requirement: Репозиторий не содержит MCP-конфигурации и секретов

В репозитории MUST NOT храниться конфигурация MCP-клиентов (в частности, workspace-конфиг ZCode) и файлы с учётными данными. Подключение документируется как персональный конфиг каждого клиента; для ZCode — юзер-скоуп `~/.zcode/cli/config.json`, запись MUST быть самодостаточной (command, args и env вместе), поскольку юзер-скоуп заменяет одноимённую workspace-запись целиком, без послойного слияния.

#### Scenario: Чистый клон

- **WHEN** репозиторий клонируют на новую машину
- **THEN** в нём нет `.zcode/config.json`, `.env` и секретов; подключение описано в README для каждого клиента

#### Scenario: Подключение в ZCode по README

- **WHEN** пользователь добавляет запись `fizikl` в `~/.zcode/cli/config.json` по инструкции из README
- **THEN** запись содержит command, args и env-блок с `LOGIN`/`PASSWORD`, сервер автоподключается в любой workspace

### Requirement: Инструменты разработчика используют те же креды

Ручной smoke-цикл SHALL получать креды тем же способом — из переменных окружения процесса, без файлов `.env`.

#### Scenario: Smoke без кредов

- **WHEN** smoke запускают без `LOGIN`/`PASSWORD` в окружении
- **THEN** он завершается с той же русскоязычной подсказкой про env

#### Scenario: Smoke с inline-env

- **WHEN** smoke запускают как `LOGIN=… PASSWORD=… npm run smoke`
- **THEN** прогон начинается с шага проверки кредов и идёт дальше по циклу
