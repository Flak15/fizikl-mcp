# 03: Чтение продуктов: `search_food` с гидратацией + `get_food`

**What to build:** Путь чтения базы продуктов: `search_food(query, limit=10)` ищет по русской базе (search v1), берёт топ-N ID (N ≤ 10, по умолчанию 10) и сразу докупает карточки продуктов — в ответе карточки с порциями, где подсвечена порция-«г» (`metric_weight: 1`) как способ записать «просто граммы». `get_food(id)` — точечный осмотр карточки: КБЖУ порций, порции с `metric_weight`, `cooking_coefficient`. Описания инструментов и человекочитаемые поля — русские.

**Blocked by:** 01 (Каркас MCP-сервера + авторизация Физикла + `list_meals`)

**Status:** done

- [x] `search_food("гречка")` возвращает карточки топ-10 с названиями и порциями, а не голые ID
- [x] В каждой карточке порция-«г» помечена как способ записи «просто граммы»
- [x] `limit` работает: ограничивает число карточек, максимум 10, невалидное значение — русскоязычная ошибка
- [x] `get_food(id)` возвращает карточку со списком порций (id, название, `metric_weight`)
- [x] Пустой результат поиска — понятный русский ответ, не ошибка
- [x] Юнит-тесты на моках: гидратация топ-N, пустая выдача, 404 карточки

## Comments

- Реализовано на ветке `ticket/03-search-get-food`, в integration через 08f830a. `search_food(query, limit=10)` — search v1 с `page_size=limit`, гидратация ровно топ-N карточек (санкционированное отступление от тонких обёрток, ADR-0004); порция «г» (`metric_weight: 1`) подсвечена как «просто граммы» и в поиске, и в `get_food`; невалидный `limit` — русская ошибка до любых запросов; пустая выдача — русский ответ, не ошибка.
