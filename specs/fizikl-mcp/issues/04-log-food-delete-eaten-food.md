# 04: Запись: `log_food` с дефолтами + `delete_eaten_food`

**What to build:** Путь записи в дневник: `log_food(serving_id, serving_amount, meal?, eaten_date?)` создаёт съеденное (массив из одного элемента в `create-list`), `delete_eaten_food(id)` удаляет запись. Дефолты: `eaten_date` → сегодня по локальной таймзоне машины; `meal` → по локальному времени окнами [04:00,12:00) `zavtrak`, [12:00,18:00) `obed`, [18:00,21:00) `uzhin`, [21:00,04:00) `perekus`; явный аргумент перекрывает автоподбор; применённый дефолт всегда виден в ответе. Демо serving_id можно взять из `docs/research/pht-api.md`.

**Blocked by:** 01 (Каркас MCP-сервера + авторизация Физикла + `list_meals`)

**Status:** done

- [x] Окна времени: 04:00–12:00 завтрак, 12:00–18:00 обед, 18:00–21:00 ужин, 21:00–04:00 (через полночь) перекус

## Comments

- Реализовано на ветке `ticket/04-log-delete-food`, в integration через 156d425. `log_food` шлёт create-list массивом из одного элемента (ADR-0004, тело запроса проверено тестом дословно); дефолты по ADR-0005 — `eaten_date` → сегодня локальной таймзоны, `meal` по окнам [04,12)/[12,18)/[18,21)/[21,04), явный аргумент перекрывает, применённые дефолты названы в ответе («подобран по времени (сейчас …)»).
- Слаг пре-валидируется по живому `meal/list` (поддержаны пользовательские приёмы из `list_meals`), кэш на время жизни процесса; `serving_amount < 0.01` и неизвестный slug — русская ошибка до записи, дневник нетронут. `delete_eaten_food`: 204 → удалено, 404 → «возможно, уже удалена».
- Появление записи в списке за дату — по ADR-0006 это ручной smoke на проде (тикет 06), автотесты пишут только в мок.
- По итогам код-ревью: `createEatenFood` возвращает структурный `{id, meal, eatenDate}` (текст ответа байт-в-байт тот же) — smoke и гарантированная очистка не зависят от формулировок.
