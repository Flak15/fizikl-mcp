# 01: Каркас MCP-сервера + авторизация Физикла + `list_meals`

**What to build:** Первый end-to-end путь: запускаемый stdio-сервер (TypeScript + `@modelcontextprotocol/sdk`), который при вызове инструмента лениво логинится в Физикл по кредам из `.env` (`LOGIN`, `PASSWORD`), получает JWT-пару, держит access в памяти, персистит refresh в `~/.fizikl-mcp/auth.json` (права 600), при 401 делает refresh, при смерти refresh — полный ре-логин, ходит в микросервисы с Secret-схемой. Инструмент `list_meals()` возвращает приёмы пищи (slug + название) с русским описанием. Юнит-тесты auth-флоу на vitest + undici MockAgent (без живых запросов; см. ADR-0006). Старт README с конфиг-сниппетом для LLM-клиента.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] `npm run build` (tsc → `dist/`) и запуск сервера по stdio работают на Node 24
- [x] Ленивый логин: сервер не делает сетевых запросов до первого вызова инструмента
- [x] Refresh-токен переживает рестарт сервера (ре-логин не чаще раза в ~30 дней), файл `~/.fizikl-mcp/auth.json` с правами 600

- [x] `list_meals()` возвращает приёмы пищи: `zavtrak`/`obed`/`uzhin`/`perekus` и пользовательские, если есть
