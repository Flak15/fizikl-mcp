# fizikl-mcp

MCP-сервер (Model Context Protocol) для дневника питания [Физикл (Physical Life)](https://pht.space/app): тонкие обёртки над API `*.pht.space`. Локальный stdio-процесс для LLM-клиентов (ZCode, Claude Desktop, Cursor, Claude Code).

Реализованы все шесть инструментов: приёмы пищи, поиск продуктов, карточки с порциями, запись съеденного, итоги дня и удаление записей. Архитектура и решения — в `docs/adr/`, карта API — в `docs/research/pht-api.md`.

## Требования

- Node.js ≥ 20 (разрабатывалось на 24)
- Аккаунт Физикла

## Установка

```bash
npm ci
npm run build
```

Креды (`LOGIN`/`PASSWORD` аккаунта Физикла) в репозитории не хранятся: клиент передаёт их серверному процессу через `env`-блок своей MCP-конфигурации — см. [Подключение к клиенту](#подключение-к-клиенту).

Авторизация ленивая: сервер логинится при первом вызове инструмента. Refresh-токен (живёт 30 дней) сохраняется в `~/.fizikl-mcp/auth.json` с правами 600 — ре-логин нужен не чаще раза в месяц.

## Подключение к клиенту

Общий вид: клиент запускает процесс `node <путь-к-проекту>/dist/index.js` (путь — абсолютный) и передаёт `LOGIN`/`PASSWORD` через `env`-блок записи `fizikl`. Запись самодостаточна: `command`, `args` и `env` задаются вместе.

**ZCode** — юзер-скоуп `~/.zcode/cli/config.json`, серверы вложены в `mcp.servers` (действует во всех workspace, статус виден в Settings → MCP). Юзер-скоуп заменяет одноимённую workspace-запись из `.zcode/config.json` целиком, без послойного слияния полей, — поэтому держите в ней все три поля сразу.

```json
{
  "mcp": {
    "servers": {
      "fizikl": {
        "command": "node",
        "args": ["/absolute/path/to/fizikl-mcp/dist/index.js"],
        "env": {
          "LOGIN": "you@example.com",
          "PASSWORD": "ваш-пароль"
        }
      }
    }
  }
}
```

**Claude Desktop** (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "fizikl": {
      "command": "node",
      "args": ["/absolute/path/to/fizikl-mcp/dist/index.js"],
      "env": {
        "LOGIN": "you@example.com",
        "PASSWORD": "ваш-пароль"
      }
    }
  }
}
```

**Cursor** (`~/.cursor/mcp.json`) — та же запись с `command`/`args`/`env`, ключ верхнего уровня `mcpServers`, как у Claude Desktop.

**Claude Code**:

```bash
claude mcp add fizikl \
  -e LOGIN=you@example.com \
  -e PASSWORD=ваш-пароль \
  -- node /absolute/path/to/fizikl-mcp/dist/index.js
```

После подключения инструменты агента доступны с префиксом `mcp__fizikl__*` (например, `mcp__fizikl__search_food`).

## Инструменты

Все ошибки возвращаются на русском языке; при сообщениях о входе проверьте `LOGIN`/`PASSWORD` в `env`-блоке конфигурации MCP-клиента.

### `list_meals()`

Приёмы пищи дневника с их slug: `zavtrak`, `obed`, `uzhin`, `perekus`. Slug нужен при записи съеденного.

### `search_food(query, limit?)`

Поиск продуктов по русскому названию («гречка», «творог 5%»).

- `query` (string, обязательно) — название продукта по-русски.
- `limit` (целое 1–10, по умолчанию 10) — сколько карточек вернуть.

Возвращает карточки топ-N результатов сразу с порциями (порция «г» подсвечена); для КБЖУ порций и id порций — `get_food`.

### `get_food(id)`

Карточка продукта по `id` из `search_food`: порции с id и весом, КБЖУ порций, коэффициент варки. Порция **«г»** (`metric_weight: 1`) — способ записать «просто граммы»: `serving_amount` = вес в граммах.

### `log_food(serving_id, serving_amount, meal?, eaten_date?)`

Записать съеденное в дневник.

- `serving_id` (число, обязательно) — id порции из `get_food`.
- `serving_amount` (число, обязательно, минимум 0.01) — количество порций; для порции «г» — граммы (например, `200` = 200 г).
- `meal` (string, необязательно) — slug из `list_meals`. **Дефолт:** подбор по локальному времени машины — окно 04:00–12:00 → `zavtrak`, 12:00–18:00 → `obed`, 18:00–21:00 → `uzhin`, 21:00–04:00 → `perekus`.
- `eaten_date` (YYYY-MM-DD, необязательно). **Дефолт:** сегодня по локальной таймзоне машины.

Явный аргумент всегда перекрывает дефолт; фактически применённые приём пищи и дата видны в ответе. Ответ содержит `id записи` — он нужен для удаления.

### `delete_eaten_food(id)`

Удалить запись о съеденном по её `id` (из ответа `log_food`).

### `get_day_summary(date?)`

Итоги дня (калории, белки, жиры, углеводы, клетчатка, вес еды) и записи о съеденном, сгруппированные по приёмам пищи.

- `date` (YYYY-MM-DD, необязательно). **Дефолт:** сегодня по локальной таймзоне машины.

## Разработка

```bash
npm test          # юнит-тесты (vitest + undici MockAgent, без живых запросов)
npm run typecheck # tsc --noEmit
npm run build     # tsc → dist/
npm run dev       # запуск без сборки (tsx src/index.ts)
```

### Smoke на проде

`npm run smoke` — ручной живой цикл (ADR-0006): логин → `search_food` «гречка» → `get_food` → `log_food` 10 г в `perekus` за сегодня → `get_day_summary` → `delete_eaten_food` → контрольное отсутствие записи. Запуск: `LOGIN=… PASSWORD=… npm run smoke`; других ручных шагов нет.

Внимание: smoke пишет в **настоящий дневник** и удаляет свою запись за собой (гарантированно, даже при сбое проверки). Дневной отчёт за дату прогона может сохранить значения дня теста.

## Безопасность

- Креды живут только в `env`-блоке персонального конфига MCP-клиента, вне репозитория; файлов с учётными данными в репозитории нет.
- `~/.fizikl-mcp/auth.json` содержит refresh-токен — файл создаётся с правами 600.
- Сервер ходит только на прод-хосты Физикла (`pht.space`, `food-tracker.pht.space`, `search.pht.space`), зашитые константами.
