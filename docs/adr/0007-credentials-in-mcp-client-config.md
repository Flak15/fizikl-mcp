# 0007. Креды — через env-блок конфигурации MCP-клиента, без `.env`

Дата: 2026-11-07
Статус: принято

## Контекст

Креды Физикла (`LOGIN`/`PASSWORD`) лежали в `.env` у корня проекта, который читал самописный `loadEnvFile()` (два пути поиска: корень проекта и cwd). Файл был известен только этому репозиторию и запуску из терминала, а workspace-конфиг `.zcode/config.json` с записью `fizikl` (command + args, без env) был закоммичен вместе с машина-специфичным абсолютным путём. Стандартный паттерн MCP-серверов (GitHub MCP и др.) другой: клиент, запускающий процесс сервера, передаёт секреты через `env`-блок своей конфигурации — «как запускать» и «с какими секретами» описаны в одном месте.

Ограничение ZCode из доков и практики: юзер-скоуп `~/.zcode/cli/config.json` заменяет одноимённую workspace-запись **целиком**, послойного слияния полей нет; `${VAR}`-подстановок в конфиг-файлах тоже нет.

## Решение

- **Вариант B3:** workspace-запись удаляется из репозитория (`git rm .zcode/config.json`), вся конфигурация переезжает в юзер-скоуп `~/.zcode/cli/config.json` полной самодостаточной записью `fizikl` — `command`, `args` и `env` вместе (слоёного слияния нет, поэтому полудописи бессмысленны). README документирует подключение для каждого клиента: ZCode (юзер-скоуп), Claude Desktop (`claude_desktop_config.json`), Cursor (`~/.cursor/mcp.json`), Claude Code (`claude mcp add -e …`).
- **`loadEnvFile()` и `.env` удаляются полностью, без dev-fallback.** Лоадер существовал ради запуска вне клиентского конфига; после переезда его единственный потребитель — smoke, которому хватает inline-env (`LOGIN=… PASSWORD=… npm run smoke`). Один источник кредов — окружение процесса.
- **Fail-fast при старте сохраняется** (ADR-0002-стиль eager-проверки не менялся здесь и ранее): без кредов сервер выходит с ненулевым кодом ещё до регистрации инструментов, конфигурационная ошибка видна сразу в Settings → MCP клиента.
- **Тексты ошибок клиенто-независимы:** «передайте через env-блок в конфигурации вашего MCP-клиента», без хардкода путей конкретного клиента (пути — в README); слова «LOGIN и PASSWORD» сохранены — на них матчатся юнит-тесты.

### Рассмотренные альтернативы

- **B1** — workspace держит command/args, юзер-скоуп добавляет только env: невозможно, слияния полей между скоупами нет, юзер-запись затирает workspace целиком.
- **B2** — полная юзер-запись плюс workspace-файл как «хинт» для свежих клонов: на этой машине файл — мёртвый груз, на чужой — сервер, падающий при старте без кредов; второй источник правды ради подсказки.
- **A** — раскоммитить `.zcode/config.json`, добавить в `.gitignore`, шаблон в README: персональный файл остаётся в дереве репозитория; раз он всё равно персональный — ему место вне репо.
- **D** — плагин ZCode с `${user_config.KEY}`: платформенно-родно, но превращает однофайловый сервер в дистрибутив — оверкилл для личного инструмента.
- **Креды через args** (`--login …`): отклонено, args видны в `ps` другим процессам пользователя; env-блок — стандарт паттерна.
- **Оставить `loadEnvFile()` как dev-fallback:** два источника кредов — два места для расхождений; механика и так мягкая (env, заданный клиентом, лоадер не переопределял).

## Последствия

- Репозиторий не содержит ни секретов, ни machine-specific конфигурации: свежий клон подключается по README, шаг с юзер-скоупом — осознанный размен за чистоту дерева.
- Пароль в plaintext в `~/.zcode/cli/config.json` — тот же уровень доверия, что `claude_desktop_config.json` и `~/.fizikl-mcp/auth.json`: персональный файл в домашнем каталоге, в git не попадает.
- **Ограничение мультиаккаунтности:** `auth.json` один на машину, поэтому клиенты с разными аккаунтами Физикла будут делить один refresh-токен и затирать друг друга. Смена аккаунта = правка env-блока конфига. Приемлемо для личного инструмента; revisit при появлении второго аккаунта.
- Smoke запускается только с inline-env; запуски «как раньше» (`npm run smoke` молча без кредов) больше не проходят — шаг «Креды из окружения» падает с той же подсказкой, что и сервер.
- ADR-0003 (персистентность refresh-токена) и ADR-0006 (smoke-цикл) не меняются задним числом: их формулировки про `.env` устарели, актуальный источник кредов — этот ADR.
